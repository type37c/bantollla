# banto — 番頭

**すべての一人親方に、番頭を。** banto は、開いた仕事を黙って死なせないための、
追記専用の台帳と規律です。

やりかけの仕事をループとして台帳に記録し、停滞したら「続ける・意識的に保留する・
意識的にやめる」の三択を必ず迫ります。「できました」という主張(claim)と、証拠で
確認された事実(verified)を区別し、台帳は追記専用・ハッシュ連鎖で、あとから
書き換えられません。人間にも、AI エージェントにも、同じ鎖と同じ門が適用されます。

## 開いた仕事は、黙って死ぬ

やりかけの仕事は、失敗して死ぬのではありません。忘れられて死にます。
アイデアは熱いうちに膨らみ、冷めると消える。「できました」は、往々にしてできていない。
会社なら誰かが見張ってくれるこれらのことを、一人でやる人は、誰にも見張ってもらえません。

江戸の商家には、番頭がいました。主人の熱に便乗せず、大福帳を守り、必要なら主人にさえ
規律を向ける役割です。火事のとき、商人は金より先に大福帳を井戸へ投げ込んだ —
帳面こそが商いの命だと知っていたからです。ただし番頭は大店にしかいませんでした。
**banto は、その番頭を道具にして、一人でやる人の手に渡すものです。**

## 三つの芯

**1. 追記専用の台帳(大福帳)** — すべての出来事をハッシュ連鎖のイベントとして
追記します。編集も削除もできません。間違えたら、訂正イベントを重ねます。
歴史は消さず、上書きもしない。だから後から読んで信じられる。git push が、現代の井戸です。

**2. ループの規律(黙って死なせない)** — 仕事は「ループ」として開き、次の一手は
常に一つ、15〜30分で終わる粒度に刻みます。同時に走らせる本数には上限があり、
停滞したループには三択が突きつけられます — 続けるか、意識的に保留するか、意識的に殺すか。
**「また今度」は選択肢にありません。**

**3. claim ≠ verified(ゲート)** — 「できました」という宣言は、成果物そのものを
証拠として結ばなければ通りません。そして宣言した本人は、自分の宣言を検証できません
(別の actor だけが verify できる)。自信の強さは、判定に使いません。
**主張と事実のあいだに、門があります。**

## 人にも、AI エージェントにも

台帳は書き手(actor)が人間か AI エージェントかを区別しません。同じ鎖、同じ門。
エージェントの「完了しました」も、人間の「明日やる」も、等しく証拠を求められます。
AI に仕事を任せる時代に必要なのは、賢いエージェントではなく、
**エージェントを信じられる根拠**です。banto はそれを記録の側から作ります。

## 使い方

Rust 製の CLI です。ネットワークも、アカウントも、他人も要りません。

```sh
cargo install --path crates/banto-cli   # このリポジトリから
mkdir ~/work && cd ~/work               # 台帳を置く作業ディレクトリで
banto init --actor あなたの名前
banto note "最初のメモ"
banto loop open kadai --title "やりかけの仕事を閉じる"
banto loop next kadai "最初の15分の一手"
banto brief
```

(リポジトリ直下ではなく、自分の作業ディレクトリで `banto init` してください。
台帳はあなたのものであり、このリポジトリに置くものではありません。)

### 主なコマンド

| コマンド | 動作 |
|---|---|
| `banto init` | ワークスペースを初期化(banto.toml・空の台帳・蔵) |
| `banto note TEXT` | アイデア・メモの捕捉(新アイデアは既定で保留場行き) |
| `banto journal --text TEXT` | 朝の統括の記帳(媒体非依存、テキストが本体) |
| `banto loop open/next/touch/close/park/kill` | ループの一生 |
| `banto brief` | 朝礼ビュー(稼働中ループを放置日数の降順で) |
| `banto gate declare/check/verify` | ゲート(証拠必須・宣言者は検証不可) |
| `banto verify [--deep]` | 台帳全検査(ハッシュ鎖・正準形・証拠) |
| `banto health` | 鐘(停滞・途絶があれば終了コード 1) |

仕様の全体は [docs/cli_spec_v1.md](docs/cli_spec_v1.md)、
語彙は [docs/types_v1.md](docs/types_v1.md)、
そして最も短い権威が **37行の契約** [docs/contract_v1.md](docs/contract_v1.md) です。
この文書に収まらないものは、契約ではなくローカルな都合である — それが設計です。

## 語彙(この道具は言葉ごと使うものです)

| 言葉 | 意味 |
|---|---|
| ループ | 開いた仕事。開く・進める・閉じる・保留(park)・殺す(kill) |
| 次の一手 | ループごとに常に一つ。15〜30分で終わる粒度 |
| 保留場 | 新しいアイデアの既定の行き先。熱が冷めても消えない場所 |
| claim / verified | 「できたという主張」と「証拠で確認された事実」。別物 |
| ゲート | claim を verified に変える門。証拠必須・宣言者は検証不可 |
| 台帳 | 追記専用・ハッシュ連鎖のイベント列。編集も削除も不可能 |
| 番頭 | この規律の執行者。主人の熱に便乗せず、決定は主人に返す |

## 拡張の作法

カーネルを触らずに拡張できます。新しい種類の出来事は `banto append TYPE --body JSON` で
今日から積めます(例: 期日は `date.pin`、番号類は `fact.pin` — 実際にカーネル改修ゼロで
運用に入った実例です)。読み方は導出ビューとして自由に作れます — 台帳は購読対象であり、
ビューはいつでも作り直せます。ライブラリとして使う場合は `banto-kernel` クレートの
`Ledger` / `Envelope` / `fold` を参照してください。

## 出自について、正直に

- この設計は、作者の前身の私有実験(研究台帳ツール、コードネーム **bgit**)の検死から
  生まれました。規律は機能したのに、規律の維持自体が仕事になって死んだ — その死因を
  不変量に変換したのが banto です。契約に出てくる「bgit G-2: 確信度の捕捉率 0.081」は、
  「自信の強さは成果をほとんど予測しなかった」というその実験の実測値で、
  confidence を判定に使わない規律の根拠です。

  行っています。本リポジトリのコードは Apache-2.0 で提供され、その特許許諾条項
  (ライセンス §3)が本コードの利用者に適用されます。隠すより先に書いておきます。
- 作者自身がこの道具で自分の仕事(特許出願そのもの)を完走させた実運用の台帳が
  一冊ありますが、それは N=1 の証拠です。あなたの一冊が二冊目になります。

## English

**banto** ("head clerk" of an Edo-era merchant house) is an append-only,
hash-chained, evidence-bearing event ledger with a discipline layer for
solo workers and AI agents: open loops must be closed, parked, or killed —
never silently dropped; and a *claim* is not *verified* until evidence is
attached and a **different** actor confirms it. Confidence is recorded but
never used as judgment. Rust CLI, local-only, no accounts. Japanese-first;
issues in English are welcome.
